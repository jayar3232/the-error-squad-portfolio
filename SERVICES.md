# Weather and messaging services

## Weather

Enter a city name. If several places share its name, add a country after a comma. Open-Meteo geocodes the first matching place, then supplies model-based current conditions and up to five daily forecasts. The displayed date and time are local to the forecast city. The service returns Celsius, relative humidity in percent and wind speed in km/h. The interface converts temperatures for the Fahrenheit view.

No account or API key is needed for this non-commercial classroom portfolio. Live readings require internet access to both the geocoding and forecast endpoints. A failed search, connection timeout, rejected request or incomplete current reading raises an error. Any readings marked **sample** belong to an offline example. No sample is generated by the service adapter.

[Forecast documentation](https://open-meteo.com/en/docs) · [Geocoding documentation](https://open-meteo.com/en/docs/geocoding-api) · [Usage terms and attribution](https://open-meteo.com/en/terms)

## Local chat

Leave both configuration fields blank to use local mode. Your own browser holds the message history. To talk between tabs, open the same project URL in two tabs on the same origin and browser profile. Use different display names. A message or typing indication appears only when someone sends or types something. The adapter uses BroadcastChannel, with storage events when that API is unavailable. Browsers may isolate individual files under file:// or restrict storage in private tabs. Serving the folder on localhost gives the tabs a common origin.

## Connect genuine multi-device messaging

1. Create or select your group's Supabase project. Under **Connect** or project API settings, copy its HTTPS Project URL and its **publishable key**. A legacy anon key also works. Keep secret and service-role keys on a trusted server.
2. In the project's Realtime settings, enable public channel access if necessary. This portfolio uses a public Broadcast channel with a shared room name. Participants with the public configuration can subscribe and send. Display names are self-chosen. No SQL tables, login, database policies or hosted message archive are needed for this classroom room.
3. Edit `js/services/chat-config.js`. Set `url` and `key` to the copied values and choose a unique `room` for the group. Use the exact same three values on each device.
4. Serve the folder or deploy the updated files. Both devices need internet access to the Supabase project, its websocket and jsDelivr. The browser client is fetched only for configured remote rooms.
5. Open Chat on two devices. Wait for the connected state on both devices. Enter different display names, type, then send a message. The sender receives a server acknowledgement and the other active participant receives the message. A server acknowledgement confirms server receipt. It does not confirm that another participant read it.

Realtime Broadcast distributes events to connected subscribers. Peers who join later see only the history already saved in their own browser. A disconnected or partially configured shared room reports an error. Removing both credentials and reloading restores local mode.
